### H3. `isAdmin()` бота = «у пользователя есть хоть одна роль»

`bot/index.js:250-261`:

```js
async function isAdmin(serverId, userId) {
  try {
    const member = await api("GET", `/servers/${serverId}/members/${userId}`);
    const server = await api("GET", `/servers/${serverId}`);
    if (server.owner === userId) return true;
    // Check if member has any roles (basic permission check)
    return member.roles && member.roles.length > 0;   // ← вот это
  } catch { return false; }
}
```

`grep -c "isAdmin(SERVER_ID" bot/index.js` → **34** из 38 команд: `kick`, `ban`, `unban`, `mute`, `purge`, выдача XP, управление турнирами, `stream start/stop`, автомод. Все они открываются любому, кому выдали **любую** роль — включая чисто косметическую (цвет ника, «Стример», «Новичок»).

**Текущая экспозиция низкая**: в живой БД существуют только роли `Admin` / `Адмнистратор`, обе с полным набором прав, и назначена ровно одна. То есть прямо сейчас «есть роль» ≈ «админ». Но это ловушка, которая срабатывает молча в момент создания первой декоративной роли — а роли и уровни есть в роадмапе.

API отдаёт реальные права: у роли в БД лежит `permissions.a` (`{"high":127,"low":-1032225}`). Проверять нужно нужный бит (`KickMembers` / `BanMembers` / `ManageMessages`), либо завести явный allowlist ролей через env.

**Задачи:**
- [ ] Заменить «есть роли» на проверку бита прав либо `ADMIN_ROLE_IDS` из env
- [ ] Развести уровни: модерация (kick/ban/mute/purge) vs утилиты (XP/турниры/стримы) — сейчас всё под одним чеком

```
/etc/nginx/sites-enabled/plgvoice.conf   — mtime 24 июля 19:18
```

`diff` репо ↔ прод показывает, что коммиты `19719f48` и `02ec91f0` (помеченные в плане как ✅) на nginx **не приехали**. Разошлись:

| Правка | В репо | В проде | Реально действует? |
|---|---|---|---|
| `server_tokens off` | есть | нет | **да** — глобально из `nginx.conf:18` |
| `ssl_protocols TLSv1.2 TLSv1.3` | есть | нет | **да** — глобально из `nginx.conf:23`; TLS 1.0/1.1 отклоняются (проверено handshake'ом) |
| `X-XSS-Protection: 0` | есть | `1; mode=block` | **нет** |
| `Permissions-Policy` | есть | нет | **да** — приходит от Caddy |
| `X-Forwarded-For` / `-Proto` на `/stream/`, `/whip` | есть | нет | **нет** |

Живой ответ содержит **задвоенные security-заголовки** — nginx добавляет свой набор поверх Caddy'шного:

```
x-xss-protection: 0                 ← Caddy
x-xss-protection: 1; mode=block     ← nginx (старый файл)
strict-transport-security: ...      ×2
x-frame-options: DENY               ×2
content-security-policy: ...        ×2
```

Практический риск от самого дублирования близок к нулю (CSP одинаковые и складываются по пересечению; XSS Auditor выпилен из всех современных браузеров). Реальная проблема — **процессная**: файл в репо и файл в проде разъехались, а трекер считает пункты закрытыми. Плюс один содержательный дефект: `/stream/` в проде отдаёт бэкенду только `X-Real-IP`, без `X-Forwarded-For`/`-Proto`.

**Задачи:**
- [ ] `sudo cp plgvoice.conf /etc/nginx/sites-enabled/plgvoice.conf && sudo nginx -t && sudo systemctl reload nginx`
- [ ] Убрать дубликаты: решить, кто владелец security-заголовков — nginx (край) или Caddy, — и снять их у второго
- [ ] Проверить после reload: одиночные заголовки, `/stream/` отдаёт XFF

### M5. `member_fetch_all.rs:43` — panic по запросу (латентный)

```rust
let mut users = User::fetch_many_ids_as_mutuals(db, &user, &user_ids).await?;
members.sort_by(...); users.sort_by(...);
if let Some(true) = options.exclude_offline {
    let mut iter = users.iter();
    members.retain(|_| iter.next().unwrap().online);   // ← :43
}
```

Код предполагает `users.len() == members.len()`. Но `fetch_many_ids_as_mutuals` (`crates/core/database/src/models/users/model.rs:380-394`) маппится по результату `db.fetch_users(ids)` — а `$in`-выборка возвращает **только существующие документы**. Если у члена сервера пропал документ пользователя (удалённый аккаунт, недоведённое удаление), `users` короче `members` → `iter.next()` вернёт `None` → panic.

Триггер — любой аутентифицированный пользователь: `GET /servers/<id>/members?exclude_offline=true`. Rocket ловит panic и отдаёт 500, процесс не падает, но эндпоинт ломается для этого сервера навсегда, пока висит сирота.

**Сейчас не эксплуатируется** — проверил живую БД: 4 member-строки, 3 уникальных пользователя, **0 сирот**. Станет реальным при первом удалении аккаунта.

- [ ] `.retain()` → `zip` по отсортированным спискам либо `while let Some(u) = iter.next()` с graceful-веткой
